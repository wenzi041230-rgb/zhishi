# ESP32-S3 录音器 V1 环境与工程骨架

## 用户目标

为自绘 PCB、ESP32-S3-MINI-1、双数字麦克风和 TF 卡建立 Windows ESP-IDF 开发环境与 V1 工程。

## 已确认结论

- 2026-11-25 官方发布页将 ESP-IDF v6.1.1 标为最新发布；官方 Windows 指南推荐 EIM，VS Code ESP-IDF 扩展可识别 EIM 安装。
- EIM 已安装并选中 ESP-IDF v6.1.1。VS Code Espressif IDF 2.3.0 工作区选择该版本及目标 esp32s3。
- 使用 EIM 激活的工具链和较短的构建目录执行 idf.py -B <build-dir> build，完整构建返回 0。应用镜像 170000 字节，另有引导程序与分区表。esptool image-info 核验芯片为 ESP32-S3、SDK 为 v6.1.1、镜像校验和有效。

## 决策与依据

- 工程目标为 esp32s3；硬件引脚、麦克风接口类型、采样格式与 TF 总线宽度均待原理图确认。
- V1 先提供启动日志、采集/存储/按键/上传接口边界及独立 PCM WAV 写入器，避免猜测硬件配置。

## 操作与产物

- 工作区 outputs/esp32s3_recorder_v1 中建立可供 EIM + VS Code 打开的 ESP-IDF 工程和 README。
- README 记录安装、构建、烧录、监视步骤及硬件决策清单。

## 待确认或待实测

- 模组完整后缀、Flash/PSRAM、原理图和 GPIO 表、双麦克风型号/接口、TF 接线、按键接线与目标音频格式。
- 实板确认下载接口、Flash 参数和 COM 口后，再验证烧录、启动日志及录音。

## 可复用知识

- VS Code 在 EIM 安装前启动扩展时曾报找不到 CMake，工具装好后重新加载窗口即可识别。
- Windows 长工程路径可能触发 CMake 对象文件路径警告。可在工程的 .vscode/settings.json 设置 idf.buildPath 为较短的绝对路径，并让命令行以 idf.py -B 使用同一目录。
- 构建成功只证明固件编译，双麦采样、TF 写入与断电恢复需要实板验证。
## 首次上板准备

- 本地核对原理图导出和厂商数据手册，工程选择与模组匹配的 4 MB Flash 及原生 USB Serial/JTAG 控制台。更改记录到 sdkconfig.defaults，已有生成配置也需更新，重编通过。
- 首次上板先识别 USB 枚举新增端口，使用 esptool flash-id 核对芯片和 Flash，再按已确认的目标烧录和监视启动日志。原有串口不能作为板卡身份的证据。
- 原理图网络映射留在本地工程 README。若 SD 卡检测使用绑带引脚，需检查有卡和无卡在复位时的电平；保存该约束，实际行为仍待实测。
- 当前未发现目标板原生 USB 串口，尚未验证 Flash 实测容量、烧录或录音。

## v1.0.0 固件交付

- 已实现 48 kHz / PCM16 双声道 PDM、按键启停、RGB 状态、TF 四线 SDMMC 写 WAV，以及本地 Wi-Fi 热点下载完成录音。录音与导出独占卡访问；热点密钥由本地 TF 文件配置，日志和导出接口禁止提供密钥。
- 录音期间用有限缓冲隔离 DMA 与 TF 写入，出现溢出时显式中止。周期性同步 PCM，正常停止后写最终头、关闭并发布 WAV。中断保留临时文件，恢复脚本基于可读完整 PCM 帧生成新文件。
- ESP-IDF v6.1.1 / esp32s3 完整链接通过，应用 964736 字节，1 MiB 应用分区余约 8%。合并镜像包含引导程序、分区表和应用，已核对段偏移、芯片、4 MB Flash 配置与镜像校验。产物位于工作区 outputs。
- 主机验证覆盖按键消抖、时钟回绕、WAV 头与 PCM 载荷、注入同步失败、临时文件恢复与下载文件名限制。按用户要求暂缓烧录。实板供电、TF 持续写入、PDM 声道、无线下载与拔卡仍待验证。

## v1.0.1 发布前复核

- 确认并修复忙转闲期间的按键消抖可能误触发录音、五位录音编号到上限后无法复用空号、无线导出停止失败后无法重试，以及导出提前读到文件尾仍被标记为完成的问题。文件编号回绕继续保护已完成和临时文件。
- 主机运行录音控制器并模拟采样和存储，60 个场景通过。独立验证了 WAV 内容、短写、同步失败、临时文件恢复、下载路径和失败处理。失败录音保留临时文件，完成后才发布 WAV。
- 用 ESP-IDF v6.1.1 从默认配置完成 ESP32-S3 构建，应用分区约余 8%。合并镜像逐段比对，并校验芯片、4 MB Flash、版本、偏移和校验和。
- 尚未烧录。真实双麦声道、TF 长录和断电恢复、Wi-Fi 下载及取消后重新录音待实板验收。电脑故障模拟不可替代板上验证。

## 首次串口通信探测

- 电脑可打开 CH340 USB 转串口；仅检测到转接器时不能确认目标芯片连通。分别用自动复位和不复位执行 `esptool flash-id`，均未收到芯片串口数据。未读取到 Flash 信息，也未进行擦写。
- 外置 USB 转串口使用 3.3 V 逻辑，TX 与 RX 交叉并共地。没有自动下载电路时，在复位或上电期间拉低 GPIO0 后用 `--before no-reset` 复测。若走原生 USB，先检查设备供电和数据线并识别新增的乐鑫端口。
