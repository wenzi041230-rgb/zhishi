# WZ60 模块化验证系统规划

## 用户目标

学习 WZ60 预研资料，并规划一套可逐步搭建、可复用于后续产品的模块化验证系统。

## 已确认结论

- 资料包实际由 5 张 DWG、1 份项目建议书和 1 份 UI 定义组成；PDF 与 XLSX 各有一个内容完全相同的重复副本。
- WZ60 是带耳机支架、双声道音响、耳机磁吸充电、2.4G 耳机链路、USB 2.0 HUB、主机电源/重启控制和 SN 追溯的复合产品。
- 需求中明确的关键指标包括：双 2 英寸 5W 扬声器、耳机 1000mAh、底座 2000mAh、耳机充电 5V/1A、2.4G 传输距离 15m、耳机 20%-80% 充电小于 2h、0%-100% 小于 2.5h、底座按键寿命大于 2 万次及整机 0.8m 跌落。
- UI 表给出了耳机开关机、磁吸上下座、回连、配对、低电、休眠、充电、BQB、底座输出切换、音量、船运模式、USB HUB、主机电源和重启等状态；这些可以直接转为状态机测试用例。
- 5 张 DWG 的文件头均为 `AC1018`（AutoCAD 2004 格式）。本次环境未安装可安全离线解析 DWG 电气对象的工具，因此仅确认了板级文件和格式，尚未确认连接器针脚、网络名、测试点和电路实现。

## 决策与依据

- 平台采用“公共测试底座 + 可更换 DUT 适配板/线束 + 仪器驱动 + 数据化用例 + 结果追溯”，不做一块绑定 WZ60 的万能大板。
- 第一版先做半自动工程验证台，优先覆盖高频、可量化、可自动判定的电源、电池、USB、音频、按键灯效和状态机测试；射频一致性、声学全消声和机械跌落作为独立工位。
- 用例分三层：单板 bring-up、板间联调、整机验收。每层都记录 DUT SN、硬件/固件版本、夹具版本、仪器版本、原始测量值和判定阈值。
- 参考 [[对话知识/2026/2026-09/2026-09-01-WG800底座主板BOM核对|WG800 底座主板 BOM 核对]] 的经验，WZ60 在夹具和测试点冻结前必须先统一原理图、PCB、BOM 与固件的主版本，避免在不同版本之间拼接验证结论。

## 待确认或待实测

1. 补齐原理图、BOM、PCB 源文件/网表、连接器针脚表、测试点表和固件测试指令；当前 DWG 更像板级图纸，不能替代电气设计资料。
2. 明确电脑音频链路究竟是 USB Audio 还是 3.5mm 双插头；UI 中要求“电脑音量同步”，通常还需要 USB HID。
3. 明确电脑电源/重启是主板 `PWR_SW/RESET_SW` 干接点、隔离开漏，还是某种 USB 控制；普通 USB 数据线不能直接等同于主板开关触点。
4. 明确 2.4G 私有协议、蓝牙地址读取和 BQB 三者的关系，以及可供自动化读取的 RSSI、丢包、版本和配对状态接口。
5. 明确 USB 供电预算：双 5W 功放、HUB、底座主控和充电并发时的最大电流、限流和降额要求。
6. 统一 UI 表中的缺失编号、评审遗留项、低电阈值和灯效优先级，再冻结测试预期。

## 可复用知识

- 模块化验证的核心不是“仪器全”，而是先固定 DUT 接口契约、测量点、刺激方式、判定限值和证据格式，再把板卡适配层与公共仪器层分开。
- 每个自动用例都应包含：前置状态、刺激、观测量、限值、超时、恢复动作和保存证据；只有动作成功而没有测量值不能算通过。
- 推荐的公共模块为：可控电源/电子负载、USB 枚举与 HID/Audio/HUB、音频刺激与采集、按键继电器与 LED 传感、2.4G 功能链路、SN/版本追溯。机械寿命、跌落和射频认证应独立成专用工位。
- 第一版软件可使用 Python 调度、YAML/JSON 用例、SQLite 结果库和本地网页报告；仪器通过 SCPI/串口/USB 适配，DUT 专用部分只存在于适配器和产品驱动中。
