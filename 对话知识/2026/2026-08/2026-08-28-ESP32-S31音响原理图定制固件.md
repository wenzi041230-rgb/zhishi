# ESP32-S31 音响原理图定制固件

## 任务背景

依据项目原理图结构化导出、功能 UI 表，以及 ESP32-S31-WROOM-3、PCM5242、TPA3251、LAN8720A 器件资料，在既有蓝牙音响固件骨架上接入自研板真实引脚、DAC、功放时序、保护和面板旋钮。

## 已实现

- 新增 Board Manager 板卡 `hanako_esp32s31_hifi`，I2S 固定 GPIO42/43/44，48 kHz、16 bit、立体声、无 MCLK。
- PCM5242 使用 GPIO6/7 的 400 kHz I2C，7 位地址 `0x4C`；GPIO14 控制 XSMT，50 级音量直接映射到 DAC 数字音量寄存器。
- TPA3251 使用 GPIO3/34 控制预充和 12 V，GPIO4 复位，GPIO16 监测 FAULT，GPIO17 监测 CLIP/OTW；实现安全上电、软启动、故障静音断电、冷却重试和 12 dB 过热/削顶降额。
- GPIO35/37/38 接入编码器 A/B/按键，支持音量、静音、待机与配对状态操作；GPIO52 保持 LAN8720A 复位，未把以太网状态误作 UI 灯。
- 蓝牙 A2DP/AVRCP、加密 BLE GATT、状态队列、NVS 与双 OTA 分区继续沿用既有架构。

## 构建证据

- ESP-IDF 6.2 预览环境提交 `95e1386d`，目标 `esp32s31`，组件 `esp_bt_audio 1.1.0`。
- 完整重编译成功，主程序 3,198,272 字节，6 MiB 应用分区剩余约 49%。
- SHA-256：`E00BB6DB0C647BCC813502E01B4B398CE6EC85D588394858A490F58B50A9ACBE`。
- 镜像头核验：ESP32-S31、16 MB Flash、80 MHz、DIO，校验和与验证哈希有效。

## 关键硬件风险

- `AMP_RESET_N` 同时连接 IO4 与 SD_D0（GPIO20）。固件保持 GPIO20 高阻只能避免主动争用，不能消除 MCU 管脚互短；必须改原理图和 PCB。
- GPIO37 是 JTAG strapping 管脚，却由编码器 B 相网络 10 kΩ 上拉；建议换脚。
- GPIO36 所在 ON/OFF 电路可直接作用模块 EN，只能输入观测，无法保证软件长按关机流程。
- 原理图未提供 AUX、光纤、同轴、TF、IR、系统 RGB 灯及音调电位器的完整硬件链路。
- 模组完整容量后缀仍未通过实物丝印确认；构建暂按 16 MB Flash + 16 MB PSRAM。

## 验证边界与下一步

本次完成的是原理图映射、代码实现和离线构建；没有烧录实物，也没有证明蓝牙空口、I2C ACK、I2S 波形、DAC 模拟输出、功放时序、保护动作或扬声器声音。修正 RESET 管脚互短后，应先不上 PVDD 检查启动绑带、串口、BLE、I2C 和 I2S，再用限流电源与假负载验证功放链路。
