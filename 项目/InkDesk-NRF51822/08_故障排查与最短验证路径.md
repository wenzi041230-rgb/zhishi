# 故障排查与最短验证路径

## 最短实板验证

1. J-Link 读取芯片，确认目标为 NRF51822 XXAC、电压约 3.3 V。
2. 烧录 App-only 包和匹配 settings，复位运行。
3. 8 秒扫描 `EPD_Ink`。
4. 连接并订阅 NUS TX。
5. 依次查询：`PING`、`INFO`、`CAPS`、`STATUS`。
6. 同步时间，等待 `TIME_OK` 和 `CLK_OK`。
7. 确认屏幕有 5 V，执行 `TEST bands`。
8. 发送 BW/RED 图片，等待两个 `DATA_OK` 和最终 `SHOW_OK`。

## 症状矩阵

| 症状 | 优先检查 | 不要过早下的结论 |
|---|---|---|
| J-Link 连不上 | SWDIO、SWCLK、GND、VTref、芯片型号和速度 | 不一定是固件损坏 |
| 有 3.3 V、无广播 | App/SoftDevice/settings 是否成套、复位、X1、天线 | 编译成功不代表 BLE 已运行 |
| 能连接但不刷新 | 5 V/U13、FPC、RST、BUSY、屏幕型号 | BLE 正常不代表显示供电正常 |
| `BUSY` | 是否仍在刷新或已有 Job | 不要重复发送并覆盖状态 |
| `NO_BW` | 是否收到 BW 的 `DATA_OK` | RED 不能代替 BW |
| 图片错位或缺块 | 数据是否恰好 15,000 字节、方向、bit 顺序 | 不一定是屏幕坏了 |
| `TIME_ERR` | 月份、日期和 HH/MM/SS 范围 | 固件不会静默修正非法时间 |
| Windows 找不到服务 | GATT 缓存、旧配对、蓝牙重启 | 不一定需要重新烧录 |
| OTA 中断 | 距离、RSSI、供电、是否仍广播 DfuTarg | 正常断连是进入 DFU 的一部分 |

## 晶振诊断知识

- X1 影响高频系统和射频；X2 影响外部低频时钟。
- 当前专用测试结果为 X1、X2 均能起振。
- 正式固件仍用 RC LFCLK，所以判断 32 kHz 是否起振必须用专用测试或寄存器证据，不能只看 App 走时。
- 临时诊断固件测试后必须恢复 SoftDevice、App、Bootloader 和 settings。

## 成功边界

- `EPD_OK`：BLE NUS 命令链路正常。
- `DATA_OK`：一个平面完整收到，不代表已经刷新。
- `SHOW_OK`：SSD1683 刷新完成，是 App 标记成功的唯一依据。
- 屏幕肉眼正确：最终硬件验收；协议成功不能代替目视检查。
