# 率土之滨日常自动化边界评估

## 用户目标

在 Windows 安卓模拟器上处理每日登录奖励、贡品、免费招募及半价招募；仅允许相应半价成本，要求不违反游戏用户规定。

后续用户将当前范围调整为技术学习和路线评估：暂不讨论公开协议，考虑先静态分析 APK，再定制经 ADB 控制 MuMu 的程序。本轮没有要求立即连接模拟器或执行任务。

## 已确认结论

- 本地 APK：包名 `com.netease.stzb.netease`，版本 9.2.2，versionCode 3776213；仅 ARM64，10 个 DEX、83 个原生库。
- ZIP 全条目 CRC 和 APK v1/v2 签名校验通过。签名有效不等于官方发布者身份已经验证，尚未比较可信官方证书。
- 包含 NeoX 配置、Mono/.NET 相关运行库；14 个 NPK 承载主要资源。只读资源清单发现登录奖励、贡品与招募相关路径。
- 静态资源名称不能证明当前资格、领取状态、半价成本、实际按钮位置或服务端成功结果。
- [网易公开通用移动游戏协议](https://protocol.unisdk.netease.com/release/latest_v1.html)限制未经书面同意的逆向；辅助程序条款涉及模拟操作和自动任务，并包含公平性等适用条件。未查到仅自动领取日常福利的官方豁免。尚未确认该 APK 实际展示及账号接受的协议版本。

## 决策与依据

按用户“不违反规定”的约束停在只读检查和评估。没有交付自动领取脚本，没有安装或启动游戏，没有登录账号、领取奖励或消耗货币。继续实施且仍要求合规，需要明确允许依据或游戏方针对具体方案的授权。

后续技术评估认为该路线可行但未实测。优先分析资源索引、指定界面素材/布局和相关配置；执行程序采用截图识别、任务状态判断、ADB 单次操作和重新截图核验。完整还原原生/AOT 游戏逻辑不是首版必要条件。

程序分为设备操作、页面识别和任务三个模块。首先只读识别，再验证登录奖励、贡品、免费招募，最后处理半价；未知页面和不确定的消耗结果停止。招募前记录待确认状态，成功核验后记录完成，防止超时或重启后的盲目重试。

## 操作与产物

本地产物位于资料目录的 `08_Codex/stzb-daily-helper/`：`REPORT.md`、`architecture-notes.md`、`official-rules.md`、只读复核工具及元数据/归档目录证据。没有将 APK、游戏资源、源码、账号资料或原始聊天同步到知识库。

新增 `TECHNICAL_PLAN.md`，仅为设计评估。技术能力依据：[Android ADB](https://developer.android.com/tools/adb)、[Android 触摸交互](https://developer.android.com/agents/skills/devtools/android-cli/references/interact)、[MuMu ADB 连接](https://mumu.163.com/help/20240807/40912_1073151.html)。连接时读取实际实例端口并绑定 serial，不固定猜端口。游戏自绘按钮是否暴露 UI 节点需实际验证。

## 待确认或待实测

- 实际接受的协议和游戏方对具体日常脚本的答复。
- 模拟器 ARM64 兼容性、当前入口及 UI 节点、免费次数和半价实际成本。
- 日常领取与招募均为 NOT TESTED，未验证重复消耗防护和异常恢复。
- 首版优先建立只读截图识别；最高风险是游戏已完成招募但本地未确认，重试造成额外消耗。

## 可复用知识

先区分用户授权、技术可行性和第三方服务规则。范围小、个人自用或只使用正常点击都不是官方允许的证据。保持 PASS 与 NOT TESTED 分开，避免把静态分析包装为真实账号功能验收。
