# CameraGuardian 切换 WPS 联动

## 用户目标

把“有人靠近”和“人脸转向摄像头”的弹窗提醒改为立即切换到 WPS：后台已有 WPS 就复用，窗口未最大化就最大化；没有可用 WPS 窗口才新开 WPS。新增默认开启的“忽略离摄像头最近的人”，最近者的靠近和看向动作均不触发 WPS，其他人仍可触发。联动不能损害实时识别响应。

## 已确认结论

- 本机 WPS 主窗口可通过真实进程路径识别，不能依赖窗口标题包含 WPS，也不能把云服务进程当作可用主窗口。
- 源码实测把一个已最小化的 WPS 原窗口恢复、置前并最大化约需 19.8 毫秒；窗口句柄保持不变，未启动新实例。
- 打包 EXE 的 WPS 检查退出码为 0，检查时前台窗口确认为同一个 WPS，且最大化状态为真。
- 打包版 8 秒真实摄像头检查退出码为 0；告警到确认 WPS 前台且最大化的 5 个保留样本中，中位数约 12.8 毫秒，最大约 16.8 毫秒。
- 86 项自动测试通过，包括已有窗口复用、没有窗口时单次启动、置前失败不新开、其他虚拟桌面不重复启动、50 次突发告警合并为一次启动、最近者过滤和旧设置迁移。
- 单人场景会被判为最近者，因此其靠近和看向信号都被过滤；两人场景只保留较远者的动作 ID。

## 决策与依据

- WPS 查找、启动、轮询、最大化和置前在一个长期动作线程中执行；视觉线程和 Tk 主线程只发布轻量信号。
- 通过顶层窗口对应的真实进程路径和严格 exe 白名单识别 WPS，排除工具窗口和云服务进程。
- 复用窗口时先请求最大化和置前，再核验前台进程确实属于 WPS、目标主窗口确实最大化；请求投递不等同于完成。
- 没有窗口时在启动前再次枚举，防止竞态重复启动；冷启动后短间隔轮询可用窗口，最长约 12 秒，可在程序退出时取消。
- 其他虚拟桌面的 WPS 或前台激活被系统拒绝都作为明确失败状态，不以启动新 WPS 掩盖。
- 最近者从全部人体检测框中按面积最大者选择，而不是从正在动作的人中选择；因此静止的近人也会被正确豁免。
- 最近者过滤发生在生成 `TrackedAlertController` 输入之前，并先完成无轨迹兼容兜底，避免最近者因兼容 ID 被重新放行。

## 待确认或待实测

- 为避免关闭用户可能有未修改的文档，本次没有真实关闭所有 WPS 后测试冷启动；该分支已通过可控替身自动测试和打包导入检查。
- Windows 对后台程序抢占前台有限制，当前机器的通过结果不能保证所有桌面、权限级别、锁屏或系统菜单状态都能瞬间切换。
- WPS 冷启动耗时取决于安装、插件、磁盘和首次启动状态，不计入已有窗口约 12.8 毫秒的实测。
- 最近者是基于单目人体框面积的距离代理，不是真实深度测量；坐姿、遮挡、裁切或检测框交叠可能改变排序。

## 可复用知识

- 对实时视觉工具，外部应用联动必须与采集、推理和界面线程隔离，并使用单次合并避免事件风暴。
- Windows 窗口动作的成功判据应是事后状态：前台应用身份与最大化状态，而不是 API 调用返回已受理。
- “后台已打开”应按可用顶层窗口判断；仅有服务进程、工具窗口或其他虚拟桌面窗口时要单独处理。
