# GS Capture Studio 新会话采集与桌面导入验收

## 用户目标

根据既有知识记录继续下一步，实际完成一条新的手机采集、GSX 导出与桌面接收检查。

## 已确认结论

- 2026-09-28 新会话约 55.052 秒；679 条帧记录、679 个 JPEG、手机状态与 GSX 帧数一致。679 个 JPEG 均可解码，尺寸均为 640×480。
- ARCore Pose 为 TRACKING 且完整，图像与 Pose 最大时间差约 4.029 ms；IMU 为 5735 行，包含加速度计与陀螺仪，GSX 包内外 IMU 哈希相同。
- 桌面单会话导入终态为 `IMPORTED_PASS`，质量报告 `PASS`，684 个传输文件逐一完整性检查通过，错误和警告均为零；再次扫描得到 `ALREADY_IMPORTED`。
- 采集账本中未匹配、复制、编码、队列和停止待处理计数均为零。此次只证明会话内容及命令行接收链路；不证明 COLMAP、Gaussian 或视觉重建质量。
- 首轮 Windows x64 便携 ZIP 哈希与旁侧校验文件一致；在含中文和空格的目录解压后，EXE 可启动并响应、空闲正常关闭。该轮尚未点击导入，后续窗口验收见下节。

## 桌面窗口续验收

- 窗口新增可选的单会话过滤，填写 `session-数字` 时只扫描指定会话；格式错误在连接前提示。底部安全提示的布局已修正，实际窗口检查可完整显示。
- 一条较早完成的真实会话通过源码窗口接收了 873/873 个文件，传输清单与 GSX 结构有效，但质量报告为 FAIL：868 帧中 18 帧的图像与 Pose 时间差超过 5 ms，最大约 8.691 ms。失败产物保留，未改写为 PASS。
- 更新后的 Windows x64 便携 EXE 在含中文和空格的目录运行，通过窗口限定并接收另一条会话。684/684 个文件完整接收，679 帧质量 PASS，无残留 partial，状态队列只有指定会话。实际窗口显示文件数进度；完成后的 PASS 由落盘状态及同一窗口代码重新读取的列表核对，未取得便携窗口终态截图。关闭请求后程序在 15 秒内退出。
- Python 全量测试 80/80 与编译检查通过。新版便携 ZIP 为 998 个条目，未包含运行会话、样例、测试或移动端目录，SHA-256 为 `7BA6DC36E358CBAFEA0C93D3A32AF6E4E0B545B1693E02DA8300C502D44555D3`；旧包未覆盖。
- 质量报告根据采集策略分别显示源时间戳空洞门槛：直接同帧路径 250 ms，旧路径 50 ms。新版真实 PASS 报告已显示 250 ms。

## 决策与依据

- 质量报告的 PASS 是数据完整性和当前 GSX 契约结论。实测平均保存率约 12.32 FPS，低于状态中的 30 FPS 目标，不能宣称性能目标已通过。
- 修正前直接同帧采集路径以 250 ms 判定源时间戳空洞，但质量报告文字写成 50 ms。此次最大源间隔约 100.87 ms，因此计数 0 符合代码行为；文字口径已在后续窗口验收中修正。

## 操作与产物

- 新会话完成采集、导出、只导入该会话、质量核对与重复扫描。
- 用户可读验收记录和质量 JSON 已单独保存；原始会话文件保存在本地工作目录，未放入知识库。

## 待确认或待实测

- 明确实际保存帧率门槛，若要接近 30 FPS，需测量 ARCore、编码、温度与保存路径吞吐。
- 真实桌面窗口接收、状态队列 PASS/FAIL 与安全退出已完成本机有限验收；无 Python 主机、只读程序目录、ADB 缺失及断电恢复仍待测。
